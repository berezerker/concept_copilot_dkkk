# Ветвление и порядок работы

Схема простая: `main` — то, что можно отдавать сотрудникам, `develop` — текущая разработка, короткие ветки задач.

```
main      ●───────────────●──────────────●      релизы (теги v0.x.y)
           \             / \            /
develop     ●──●──●──●──●───●──●──●──●─●        интеграция, всегда рабочая
               \    /          \   /
feature/…       ●──●            ●─●             одна задача = одна ветка
                                       hotfix/… ← от main, обратно в main и develop
```

## Ветки

| Ветка | Откуда | Куда сливается | Назначение |
|---|---|---|---|
| `main` | — | — | Стабильная версия для демо и сотрудников. Прямые коммиты запрещены, только PR из `develop` или `hotfix/*` |
| `develop` | `main` | `main` (релиз) | Текущая разработка; всё, что здесь, прошло быстрые тесты |
| `feature/<коротко>` | `develop` | `develop` | Новая функция: `feature/excel-batch-read`, `feature/kpki-docx` |
| `fix/<коротко>` | `develop` | `develop` | Исправление, найденное в разработке или в E2E-отчёте |
| `hotfix/<коротко>` | `main` | `main` и `develop` | Срочное исправление выпущенной версии (например, перед демо) |
| `experiment/<коротко>` | `develop` | никуда или `develop` | Пробы (новый промпт, другая LLM); можно удалить без сожаления |

## Цикл задачи

1. `git switch develop && git pull`
2. `git switch -c feature/имя`
3. Небольшие коммиты, сообщение в повелительном наклонении: «Добавить пакетное чтение строк в Excel-движок».
4. Перед PR — проверки без Excel и сети:
   ```
   python tests/test_excel_engine.py && python tests/test_transactions.py \
     && python tests/test_harness.py && python tests/test_grading.py \
     && python tests/test_index_limitations.py && python tests/test_cell_trace.py
   ```
   Интеграционные тесты с установленным Microsoft Excel (без запросов к LLM):
   ```
   export CF_ENGINE=excel
   python tests/test_tools.py && python tests/test_credit.py && python tests/test_connectors.py \
     && python tests/test_catalog.py && python tests/test_manifest.py
   ```
   В Excel-режиме подготовка кэша формул синтетических книг также выполняется Excel, без `soffice`.
   Для приёмки конкретного драйвера на большой обезличенной модели выполните
   `python -m tests.e2e.verify_cell_stress --model путь.xlsx --metric dscr --period 2026 --driver-query цена --driver-period 2026`.
   Выберите поисковую подпись и период, присутствующие в книге. Проверка подтверждает привязку в отдельном кэше,
   находит цепочку, сравнивает эффект −10% и сверяет базу после отката. Она выполняется локально через Excel.
   Для нескольких периодов и совместного шока используйте
   `python -m tests.e2e.verify_stress_matrix --model путь.xlsx --metric dscr --period 2026 --period 2027 --driver цена -10 --driver ставка 10`.
   Проверка измеряет эффект каждого входа, сверяет совместные сценарии при разном порядке записей и сравнивает
   итог инструмента агента с прямым пересчётом Excel. После каждого сценария проверяется возврат к общей базе.
   Этот же прогон проверяет интерфейс сервера для подготовки, запуска и чтения истории сценариев. Для проверки
   выбора инструментов через LLM используйте кейс `verified_excel_scenario`. Его формулировка рассчитана на
   книгу, в которой есть обозначенные в запросе тариф и ключевая ставка за 2026–2027 годы.
5. PR в `develop`, описание: что поменялось и как проверено. Слияние — squash, ветку удалить.

## Релиз

1. На `develop` прогнать полный E2E на обезличенных моделях: `run_eval.command` (или `python -m tests.e2e.run_eval … --fresh`).
   Условие релиза: нет FAIL по ошибкам и инструментам, судья — не ниже, чем в прошлом релизе.
2. Поднять `APP_VERSION` в `app/server.py` (формат `ГГГГ-ММ-ДД.N`) и дописать раздел в `CHANGELOG.md`.
3. PR `develop → main` (merge-коммит), после слияния — тег: `git tag v0.3.0 && git push --tags`.
   Версии: `0.MINOR.PATCH` — MINOR за новые функции, PATCH за исправления.
4. Ссылку на E2E-отчёт приложить к PR.

## Hotfix

`git switch main && git switch -c hotfix/имя` → исправление + быстрые тесты → PR в `main` → тег `v0.x.(y+1)` →
тот же коммит в `develop` (`git cherry-pick` или PR `main → develop`).

## Что никогда не коммитится

`.env` (ключи), модели `.xlsx/.xlsm`, `workspace/` (копии моделей, кэш, записи демо), `demo.html`, логи и отчёты
E2E — всё это в `.gitignore`. Если ключ случайно попал в коммит — сразу перевыпустить его, а не только удалить из истории.
Реальные модели клиентов не используются ни в тестах, ни в записях демо: только обезличенные.

## Защита веток (настроить в GitHub → Settings → Branches)

- `main`: запрет прямого push, обязательный PR, 1 одобрение, запрет force-push и удаления.
- `develop`: обязательный PR, запрет force-push.
