# Как агент понимает произвольную Excel-модель

Документ для внешней оценки: что агент знает о книге, из чего он это выводит и где может ошибиться.

## Принцип

Раньше часть логики опиралась на шаблон: листы `Inputs` / `Outputs` / `Dashboard`, «основной Inputs — тот, у которого
имя короче», драйверы — строки листов «assumptions» с определёнными словами. Теперь действует одно правило:

> **Названия листов ничего не решают.** Всё выводится из трёх источников: граф формул (кто на кого ссылается),
> значения ячеек и пробный пересчёт в Excel. Слова используются только в одном месте — в лексиконе показателей
> (`concepts.py`), и только чтобы предложить кандидатов; выбор между кандидатами делает структура.

Где вывод по графу может обмануть (переключатели сценариев, `INDEX/MATCH`, `INDIRECT`), он проверяется пересчётом.

## Что строится при загрузке модели

```
книга .xlsx
  │
  ├─ 1. Индекс (index.py)        строки, подписи, периоды, формулы → граф «строка ← строка»,
  │                              именованные диапазоны, ссылки на строки целиком
  ├─ 2. Структура (structure.py) роли листов, листы-близнецы (наборы сценариев), ограничения
  ├─ 3. Справочник (catalog.py)  показатель → где лежит, где считается, как шоковать
  │        └─ проверка пересчётом: какой набор допущений выбран
  ├─ 4. Карточка (card.py)       ключевые метрики и главные допущения — из справочника
  └─ 5. Смысловой слой (semantics.py)  допущения → экономические факторы; паспорт строк (LLM)
```

Шаги 1–4 работают без LLM. Всё кэшируется по хэшу файла.

### 1. Индекс

- Подпись строки — первый текст в строке; числа левее подписи считаются нумерацией, а не параметрами.
- Периоды берутся из шапки листа (годы, кварталы, месяцы, даты).
- Граф зависимостей строится из текста формул на уровне «строка листа ← строка листа». Учитываются диапазоны,
  ссылки на строки целиком (`5:5`) и именованные диапазоны (`TaxRate`).
- Параметр одной ячейкой («Ставка налога | 20 %» без ряда по годам) распознаётся и участвует наравне с рядами.

### 2. Структура книги

Роль листа определяется по счётчикам, а не по имени:

| Роль | Признак |
|---|---|
| `inputs` — источник допущений | ≥ 3 строк с введёнными числами, на которые есть ссылки; своих расчётов ≤ 15 % от этого; на лист ссылаются другие |
| `report` — итоговый | есть расчёты, лист только читает другие (на него никто не ссылается). Либо название намекает на отчёт **и** исходящих ссылок вдвое меньше входящих |
| `calc` — расчёты | всё остальное |
| `contents`, `separator` | нет чисел, участвующих в расчётах / пустой лист |

Название листа используется в одном спорном случае (вторая строка `report`) и для подписи в интерфейсе.

**Наборы сценариев.** Листы-источники с одинаковой раскладкой (≥ 80 % подписей в тех же строках, от 15 строк) считаются
альтернативными наборами допущений. Какой из них выбран, по формулам надёжно не понять, поэтому при открытии модели
агент делает пробный пересчёт: по очереди сдвигает на 7 % до 60 строк каждого листа и смотрит, какая доля ключевых
показателей изменилась.
- Выбран тот набор, на который реагирует заметная доля показателей.
- Лист, который двигает только единичные ячейки (таблицу сравнения сценариев в отчёте), выбранным не считается.
- Если сопоставимо реагируют несколько листов, активны все: это параллельные источники, а не альтернативы.
- Строки, похожие на шкалу периодов, не сдвигаются; сломавшийся расчёт (ошибка вместо числа) считается реакцией.

Допущения невыбранных наборов исключаются из факторов, драйверов и поиска (в поиске помечаются).

### 3. Справочник модели

Справочник отвечает на вопрос «хочу стресс по выручке — где она и как её менять». В нём 26 показателей: выручка,
себестоимость, OPEX, EBITDA, EBIT, амортизация, проценты, налог, чистая прибыль, CFO, FCF, CFADS, CAPEX, обслуживание
долга, дивиденды, долг, чистый долг, денежные средства, капитал, активы и коэффициенты (DSCR, ICR, LLCR, долг / EBITDA,
чистый долг / EBITDA, рентабельность EBITDA).

Запись строится в пять шагов.

1. **Кандидаты по словам.** Лексикон (`concepts.py`) — синонимы показателя на русском и английском плюс слова-исключения
   («выручка» ≠ «себестоимость выручки», «долг» ≠ «чистый долг»). Для потоков и остатков отсекаются производные
   величины: доли, темпы, маржа. Уровень совпадения: точное → точное с уточнением в скобках → начало → вхождение.
   Берётся до 6 кандидатов по всей книге.
2. **Выбор по структуре.** Балл кандидата = уровень совпадения + «живая» строка (зависит от допущений: +3, иначе −4)
   + доля влияющих допущений относительно лучшего кандидата + положение листа в графе (ближе к итогам — выше)
   + небольшой бонус отчётному листу. Итог по компании выигрывает у сегмента, потому что у него больше допущений.
3. **Происхождение.** Найденная строка часто лишь ссылка (`=IS!4`), перевод единиц или смена знака. Агент идёт вверх
   по цепочке, пока значения пропорциональны единственному источнику, и находит строку, где показатель считается.
   Шоковать нужно её, а не копию в отчёте.
4. **Способ шока.**
   - `direct` — формула показателя на время сценария заменяется значениями; пересчитывается всё, что считается от него.
     Выбирается, если подмена по графу доходит до денежной позиции (деньги, долг, чистый долг).
   - `drivers` — меняются допущения, из которых показатель считается (по умолчанию — его «родные» факторы: для выручки
     цены, объёмы, тарифы). Величина подбирается пробным пересчётом так, чтобы показатель в среднем изменился на
     заданный процент.
   - Коэффициенты напрямую не задаются никогда.
   - **Проверка пересчётом.** При первом прямом шоке показателя агент проверяет, сдвинулись ли итоги. Если нет —
     строка справочная (например, «Выручка МСФО», от которой EBITDA не считается), способ переключается на `drivers`,
     и результат запоминается.
5. **Чего не нашли по словам.** Показатели без уверенного совпадения сопоставляет LLM: ей дают список итоговых строк
   модели (подпись, лист, единицы, три значения). Её выбор проходит ту же структурную проверку; «живую» строку
   на статичную она заменить не может. Пользователь или агент может закрепить строку вручную (`catalog_set`) —
   закрепление сильнее автоматики, сохраняется и переживает пересборку. Так же добавляются свои показатели
   («выручка сегмента А»).

У каждой записи есть уверенность (0–1), способ, которым строка найдена, альтернативы и пометки: «не зависит
от допущений», «похоже на сегмент».

### 4. Главные допущения

Раньше это были строки листов с «правильным» названием и словами из списка. Теперь — строки-допущения, от которых
по графу зависит больше всего показателей справочника; при равенстве выше рыночные факторы и строки с большим числом
ссылок. Переключатели сценариев — введённые значения с подписью про сценарий или стресс, от которых что-то зависит.

### 5. Экономические факторы

Каждое допущение выше показателей получает фактор (15 универсальных: цены реализации, объёмы, тарифы, курс, ставки,
инфляция, OPEX, CAPEX, налоги, долг…) и отраслевой подфактор. Сначала по словам подписи и единицам, затем LLM
уточняет и даёт строкам деловые названия. Допущения берутся со всех листов, не только с листов-источников.

## Как этим пользуются инструменты

Всюду, где раньше требовались `sheet` + `row`, теперь можно назвать показатель:

| Что | Запись |
|---|---|
| Шок показателя | `{"concept": "revenue", "op": "pct", "value": -10}` (+ `mode`, `via`) |
| Шок фактора | `{"factor": "price_sales", …}` |
| Шок строки, ячейки, диапазона, по смыслу подписи | `row` / `cell` / `range` / `match` — на любом листе |
| Метрика, ковенант | `{"concept": "dscr"}`, `{"concept": "net_debt_ebitda", "op": "<=", "threshold": 3.5}` |

Новые инструменты: `get_catalog` (справочник, параметры-допущения по запросу или фактору, наборы сценариев,
ограничения) и `catalog_set` (закрепить строку). Справочник целиком вставляется в системный промпт агента.
Карта модели, предпроверка, факторы, эксперт, КПКИ и стресс-пакет берут метрики и роли листов из справочника
и структуры.

## Что проверено

- **Синтетическая «чужая» модель** (`tests/foreign_model.py`): листы «Параметры / База / Стресс / Расчёт / Свод»,
  нестандартные подписи, именованный диапазон, параметры одной ячейкой, два набора сценариев. `tests/test_catalog.py`
  проверяет роли, выбор набора пересчётом, справочник и шоки по показателям.
- **Две обезличенные модели** (нефтепереработка и электроэнергетика), пересчёт в LibreOffice:

| Проверка | Нефтепереработка | Электроэнергетика |
|---|---|---|
| Найдено показателей из 26 | 23 | 25 |
| Выбранный набор допущений | `Inputs` из трёх | `Inputs` и `Inputs_стресс_КС` из четырёх |
| «Выручка −10 %» | напрямую: выручка −10 %, EBITDA −39 % (затраты не меняются) | прямая подмена не двигает итоги → через допущения: выручка −10 %, EBITDA −49 % |
| «Выручка −10 %» через допущения | допущения −13,5 %, EBITDA −6 % | допущения −11 % |

## Ограничения

- **Слова.** Лексикон — русский и английский. Показатель с необычным названием найдёт LLM или закрепит пользователь;
  без LLM он останется в списке «не найдены».
- **Прямой шок** меняет только сам показатель: затраты, которые в модели считаются от объёма, не уменьшатся вместе
  с выручкой. Агент пишет об этом в примечании. Для «честного» падения выручки нужен режим `drivers`.
- **Подгонка в режиме `drivers`** — один пробный пересчёт и линейная пропорция, «в среднем за период». По годам
  изменение показателя отличается от заданного; при слабой связи допущений с показателем (долг) подгонка грубая.
- **Переключатель сценария одной ячейкой** находится по словам в подписи («сценарий», «стресс», «case»).
- **Периоды по вертикали** (годы сверху вниз) не разбираются: такие листы участвуют в пересчёте, но шок на них
  задаётся только диапазоном. Агент предупреждает.
- **`INDIRECT` / `OFFSET`**: связи таких формул в графе не видны. Пересчёт от этого не страдает, но карта зависимостей
  и проверка «шок дойдёт до метрики» могут занижать связи. Агент показывает число таких формул.
- **Граница факт / прогноз** — текущий год; задаётся параметром, из модели не выводится.
- **Листы-близнецы** ищутся по совпадению раскладки. Сценарии, устроенные иначе (блоки на одном листе), как наборы
  не распознаются.
