# Как агент понимает произвольную Excel-модель

Документ для внешней оценки: что агент знает о книге, из чего он это выводит и где может ошибиться.

## Принцип

Раньше часть логики опиралась на шаблон: листы `Inputs` / `Outputs` / `Dashboard`, «основной Inputs — тот, у которого
имя короче», драйверы — строки листов «assumptions» с определёнными словами. Теперь действует одно правило:

> **Названия листов ничего не решают.** Всё выводится из трёх источников: граф формул (кто на кого ссылается),
> значения ячеек и пробный пересчёт в Excel. Слова используются только в одном месте — в лексиконе показателей
> (`concepts.py`), и только чтобы предложить кандидатов; выбор между кандидатами делает структура.

Где вывод по графу может обмануть (переключатели сценариев, `INDEX/MATCH`, `INDIRECT`), он проверяется пересчётом.

## Что строится при загрузке модели

```
книга .xlsx
  │
  ├─ 1. Индекс (index.py)        строки, подписи, периоды, формулы → граф «строка ← строка»,
  │                              именованные диапазоны, ссылки на строки целиком
  ├─ 2. Структура (structure.py) роли листов, листы-близнецы (наборы сценариев), ограничения
  ├─ 3. Справочник (catalog.py)  показатель → где лежит, где считается, как шоковать
  │        └─ проверка пересчётом: какой набор допущений выбран
  ├─ 4. Карточка (card.py)       ключевые метрики и главные допущения — из справочника
  └─ 5. Смысловой слой (semantics.py)  допущения → экономические факторы; паспорт строк (LLM)
```

Шаги 1–4 работают без LLM. Всё кэшируется по хэшу файла.

### 1. Индекс

- Подпись строки — первый текст в строке; числа левее подписи считаются нумерацией, а не параметрами.
- Периоды берутся из шапки листа (годы, кварталы, месяцы, даты).
- Граф зависимостей строится из текста формул на уровне «строка листа ← строка листа». Учитываются диапазоны,
  ссылки на строки целиком (`5:5`) и именованные диапазоны (`TaxRate`).
- Параметр одной ячейкой («Ставка налога | 20 %» без ряда по годам) распознаётся и участвует наравне с рядами.

### 2. Структура книги

Роль листа определяется по счётчикам, а не по имени:

| Роль | Признак |
|---|---|
| `inputs` — источник допущений | ≥ 3 строк с введёнными числами, на которые есть ссылки; своих расчётов ≤ 15 % от этого; на лист ссылаются другие |
| `report` — итоговый | есть расчёты, лист только читает другие (на него никто не ссылается). Либо название намекает на отчёт **и** исходящих ссылок вдвое меньше входящих |
| `calc` — расчёты | всё остальное |
| `contents`, `separator` | нет чисел, участвующих в расчётах / пустой лист |

Название листа используется в одном спорном случае (вторая строка `report`) и для подписи в интерфейсе.

**Наборы сценариев.** Листы-источники с одинаковой раскладкой (≥ 80 % подписей в тех же строках, от 15 строк) считаются
альтернативными наборами допущений. Какой из них выбран, по формулам надёжно не понять, поэтому при открытии модели
агент делает пробный пересчёт: по очереди сдвигает на 7 % до 60 строк каждого листа и смотрит, какая доля ключевых
показателей изменилась.
- Выбран тот набор, на который реагирует заметная доля показателей.
- Лист, который двигает только единичные ячейки (таблицу сравнения сценариев в отчёте), выбранным не считается.
- Если сопоставимо реагируют несколько листов, активны все: это параллельные источники, а не альтернативы.
- Строки, похожие на шкалу периодов, не сдвигаются; сломавшийся расчёт (ошибка вместо числа) считается реакцией.

Допущения невыбранных наборов исключаются из факторов, драйверов и поиска (в поиске помечаются).

### 3. Справочник модели

Справочник отвечает на вопрос «хочу стресс по выручке — где она и как её менять». В нём 26 показателей: выручка,
себестоимость, OPEX, EBITDA, EBIT, амортизация, проценты, налог, чистая прибыль, CFO, FCF, CFADS, CAPEX, обслуживание
долга, дивиденды, долг, чистый долг, денежные средства, капитал, активы и коэффициенты (DSCR, ICR, LLCR, долг / EBITDA,
чистый долг / EBITDA, рентабельность EBITDA).

Запись строится в пять шагов.

1. **Кандидаты по словам.** Лексикон (`concepts.py`) — синонимы показателя на русском и английском плюс слова-исключения
   («выручка» ≠ «себестоимость выручки», «долг» ≠ «чистый долг»). Для потоков и остатков отсекаются производные
   величины: доли, темпы, маржа. Уровень совпадения: точное → точное с уточнением в скобках → начало → вхождение.
   Берётся до 6 кандидатов по всей книге.
2. **Выбор по структуре.** Балл кандидата = уровень совпадения + «живая» строка (зависит от допущений: +3, иначе −4)
   + доля влияющих допущений относительно лучшего кандидата + положение листа в графе (ближе к итогам — выше)
   + небольшой бонус отчётному листу. Итог по компании выигрывает у сегмента, потому что у него больше допущений.
3. **Происхождение.** Найденная строка часто лишь ссылка (`=IS!4`), перевод единиц или смена знака. Агент идёт вверх
   по цепочке, пока значения пропорциональны единственному источнику, и находит строку, где показатель считается.
   Шоковать нужно её, а не копию в отчёте.
4. **Способ шока.**
   - `direct` — формула показателя на время сценария заменяется значениями; пересчитывается всё, что считается от него.
     Выбирается, если подмена по графу доходит до денежной позиции (деньги, долг, чистый долг).
   - `drivers` — меняются допущения, из которых показатель считается (по умолчанию — его «родные» факторы: для выручки
     цены, объёмы, тарифы). Величина подбирается пробным пересчётом так, чтобы показатель в среднем изменился на
     заданный процент.
   - Коэффициенты напрямую не задаются никогда.
   - **Проверка пересчётом.** При первом прямом шоке показателя агент проверяет, сдвинулись ли итоги. Если нет —
     строка справочная (например, «Выручка МСФО», от которой EBITDA не считается), способ переключается на `drivers`,
     и результат запоминается.
5. **Чего не нашли по словам.** Показатели без уверенного совпадения сопоставляет LLM: ей дают список итоговых строк
   модели (подпись, лист, единицы, три значения). Её выбор проходит ту же структурную проверку; «живую» строку
   на статичную она заменить не может. Пользователь или агент может закрепить строку вручную (`catalog_set`) —
   закрепление сильнее автоматики, сохраняется и переживает пересборку. Так же добавляются свои показатели
   («выручка сегмента А»).

У каждой записи есть уверенность (0–1), способ, которым строка найдена, альтернативы и пометки: «не зависит
от допущений», «похоже на сегмент».

### 3а. Реестр параметров — «что в этой книге можно менять»

Справочник показателей отвечает за типовые величины. Но в каждой модели есть свои числа: цена конкретного продукта,
коэффициент загрузки, норматив, ставка по конкретному кредиту. Для них строится реестр — **из самой книги, без
заранее заданного списка**.

**Что попадает.** Каждая строка любого листа, в которой есть введённые числа и на которую ссылается хотя бы одна
формула. Ряд по годам или одна ячейка — не важно. Не попадают строки невыбранных наборов сценариев и числа, на которые
никто не ссылается (их изменение ни на что не влияет).

**Что хранится в записи:** адрес, подпись, заголовки блока над строкой, единицы, текущие значения, экономический
фактор, на какие ключевые показатели параметр влияет по формулам, а после разбора LLM — деловое название и описание.

**Как ищется.** Слова запроса сравниваются сразу со всеми текстовыми полями записи: название и подпись (вес 3), блок (2),
фактор и подфактор (1,5), описание и лист (1). Совпадение — точное, по началу слова (окончания усекаются) или по
небольшому русско-английскому словарю общих терминов («цена» ↔ price, «бензин» ↔ gasoline). Запись подходит, если
найдено не меньше половины слов; если есть записи со всеми словами — показываются только они. Выше ставятся записи
того же фактора, что и сам запрос: «цена на бензин» → сначала цена бензина, потом акцизы на бензин.

**Как используется.** Агент обязан вызвать `find_parameters`, когда пользователь называет параметр словами, и получает
лист и строку для шока. Несколько похожих строк — перечисляет или спрашивает; ничего не нашлось — говорит об этом.
Кнопка «Параметры» показывает реестр целиком с фильтром и выгрузкой в Excel.

На двух обезличенных моделях в реестре 284 и 1 151 параметр (из них одной ячейкой — 5 и 169).

### 3б. Model Manifest — единый паспорт для агента и интерфейса

Каталог, реестр параметров, карта листов и сведения о сценариях полезны по отдельности, но раньше агенту приходилось
самому сопоставлять их между собой. Model Manifest собирает их в один контракт, который строится при загрузке и
обновляется после уточнения смыслового слоя, закрепления показателя или проверки шока пересчётом.

В паспорте есть:

- устойчивые id показателей и параметров, их адреса, единицы, периоды, факторы и известные влияния;
- отдельная уверенность в распознавании сущности, статической зависимости, способе шока и единице измерения;
- доказательства вывода: подпись и структура, граф формул, ручное закрепление, LLM-сопоставление или проверка
  пересчётом;
- зоны модели, связи между листами, активные наборы сценариев, ограничения статического разбора;
- readiness: что уже можно анализировать и стрессовать, а что требует проверки или доступно только для чтения.

Инструмент `resolve_target` переводит формулировку пользователя в сущность паспорта. Он возвращает не только
кандидата, но и явный статус: `resolved`, `ambiguous` или `not_found`. При неоднозначности агент не имеет права молча
брать первую строку — он исследует кандидатов или просит уточнение. Перед шоком также возвращаются предупреждения:
например, коэффициент нельзя задавать напрямую, у параметра не подтверждено влияние или не распознана единица.

Это не превращает агента в набор заготовленных сценариев. В свободном режиме LLM по-прежнему строит план и выбирает
инструменты под запрос. Детерминированный слой отвечает только за безопасную границу: какую сущность имел в виду
пользователь, достаточно ли данных для операции и куда именно применять изменение. Фиксированные процессы вроде
заключения для КПКИ остаются отдельным необязательным режимом.

### 4. Главные допущения

Раньше это были строки листов с «правильным» названием и словами из списка. Теперь — строки-допущения, от которых
по графу зависит больше всего показателей справочника; при равенстве выше рыночные факторы и строки с большим числом
ссылок. Переключатели сценариев — введённые значения с подписью про сценарий или стресс, от которых что-то зависит.

### 5. Экономические факторы

Каждое допущение выше показателей получает фактор (15 универсальных: цены реализации, объёмы, тарифы, курс, ставки,
инфляция, OPEX, CAPEX, налоги, долг…) и отраслевой подфактор. Сначала по словам подписи и единицам, затем LLM
уточняет и даёт строкам деловые названия. Допущения берутся со всех листов, не только с листов-источников.

## Как этим пользуются инструменты

Всюду, где раньше требовались `sheet` + `row`, теперь можно назвать показатель:

| Что | Запись |
|---|---|
| Шок показателя | `{"concept": "revenue", "op": "pct", "value": -10}` (+ `mode`, `via`) |
| Шок фактора | `{"factor": "price_sales", …}` |
| Шок строки, ячейки, диапазона, по смыслу подписи | `row` / `cell` / `range` / `match` — на любом листе |
| Метрика, ковенант | `{"concept": "dscr"}`, `{"concept": "net_debt_ebitda", "op": "<=", "threshold": 3.5}` |

Новые инструменты: `get_model_manifest` (единый паспорт и readiness), `resolve_target` (слова пользователя → сущность
или явная неоднозначность), `find_parameters` (поиск по реестру параметров), `get_catalog` (справочник,
параметры-допущения по запросу или фактору, наборы сценариев, ограничения) и `catalog_set` (закрепить строку).
Компактная готовность паспорта и справочник вставляются в системный промпт агента; подробности он запрашивает по
необходимости.
Карта модели, предпроверка, факторы, эксперт, КПКИ и стресс-пакет берут метрики и роли листов из справочника
и структуры.

## Выполнение сценария и контроль завершения

Для совместного шока точных входов `prepare_excel_scenario` разрешает адреса и периоды, показывает базу и пути
по формулам и сохраняет план текущей загрузки. `execute_excel_scenario` принимает его ID и сверяет базу в Excel
до первой записи. Для каждого входа без видимой связи с результатом требуется указать цель пробного пересчёта.
Вход и результат можно указать адресом строки из паспорта, например `Лист!34`, вместе с точным периодом.
Предпроверка выбирает единственную подходящую ячейку. При нескольких совпадениях требуется точный адрес A1.
Отдельные эффекты можно сравнить с совместным сценарием через `compare_individual`. Каждый пересчёт проверяет
общую базу входов и метрик. Итог возвращается после подтверждённого отката всей серии. При загрузке книги
планы сбрасываются. Изменение привязки или исходных значений требует подготовки нового плана.
`get_verified_excel_scenario` возвращает историю подтверждённых прогонов текущей загрузки. Сохранённые
отдельные эффекты относятся к конкретному входу и шоку, совместный эффект относится ко всей группе. Для нового
прогона всегда нужна актуальная база Excel: изменение скрытого допущения может не менять наблюдаемую базу,
но изменить реакцию модели на шок.

В карточке модели «Проверить привязки» показывает предложенную строку и альтернативы. Подтверждение сохраняется
для версии книги. Если единица строки противоречит типу показателя, она показана отдельно для проверки.

«Стресс ячейки» и инструменты `inspect_cell_stress` / `run_cell_stress` работают с одной парой A1-адресов.
Можно задать показатель и точный период или указать адрес результата вручную, в том числе в вертикальной таблице.
Поиск показывает возможные входы и явные цепочки формул, в том числе через строки без подписей. Период входа
показывается отдельно. Путь в формулах может проходить через неактивную ветку условия, поэтому влияние подтверждается
только пробным пересчётом. Имена диапазонов, структурные и динамические ссылки могут ограничить статический поиск.
Перед запуском видны исходное и предлагаемое значения. Результат включает фактический процент шока и изменение
выбранной ячейки после подтверждённого отката.

В свободном режиме агент сам выбирает последовательность инструментов. Найденную сущность можно передать шоку
через `target` (id из `resolve_target`); перед раскрытием шока цель разрешается повторно. Несколько одинаковых
названий дают `ambiguous`, даже если выдача кандидатов ограничена одним элементом. Единицы и смысл шока по-прежнему
требуют анализа: наличие точного адреса само по себе не доказывает экономическую корректность сценария.

Все сценарии Excel проходят одну транзакцию: проверить точные диапазоны и размеры данных → сохранить свежие
формулы и значения → применить шок → пересчитать → прочитать результат → восстановить книгу → пересчитать базу
и сверить контрольные показатели. Пересекающиеся диапазоны, неконечные числа и внедрение новых формул блокируются
до записи. Снимки всех диапазонов создаются до первой записи; откат охватывает и частично выполненную пакетную
команду. Проверка восстановления значений/формул точная, контрольных показателей — с относительным допуском `1e-6`.

Результат возвращается только после проверки отката. Если восстановление не подтверждается, чтение из Excel и
новые сценарии блокируются до повторной загрузки модели. Контролируются изменённые диапазоны и запрошенные метрики,
а не каждая ячейка книги; волатильные формулы в контрольных метриках могут приводить к блокировке из-за дрейфа базы.
Проверки относятся к Excel-движку. Для LibreOffice такая гарантия пока не реализована.

Excel-вызовы разных сессий внутри одного сервера сериализуются. Для исходных чисел сохраняется полная точность:
если пакетная запись округлила значение, откат повторяет диапазон через нативный интерфейс и проверяет его снова.
Excel for Mac может без ошибки неверно разложить многорядную матрицу. Поэтому проверяется и запись шока, и откат;
при несовпадении диапазон повторяется построчно, затем при необходимости по отдельным ячейкам.
Шок параметра или экономического фактора меняет только введённые числа смешанной строки; формулы сохраняются.
Явная подмена расчётного показателя остаётся отдельной операцией `mode=direct`.

Harness ведёт журнал успешных и ошибочных вызовов, включает квитанции пересчёта в результаты инструментов и
проверяет завершение плана. Финальный текст не меняет состояния шагов. При незавершённых шагах или ошибках агент
получает одну дополнительную возможность исправиться. Неустранённая ошибка инструмента приводит к сообщению
о незавершённой задаче, а не к публикации успешного заключения. Это контроль выполнения; он не заменяет независимую
проверку экономических выводов LLM.
При исправлении аргументов вызова агент передаёт `retry_of` с id прежней ошибки; независимый успешный сценарий
не снимает ошибку другого сценария. `complete=false` учитывается и в E2E-проверке.
Расчётная ошибка при подтверждённом откате не отравляет Excel-сессию: инструмент может вернуть частичный анализ,
а агент — отметить шаг пропущенным. Блокировка применяется только при неподтверждённом восстановлении книги.

## Что проверено

- `tests/test_transactions.py`: частичная пакетная запись, ошибки чтения и отката, несовпадение базы, несходимость,
  пересечения при объединении блоков, потеря числовой метрики, восстановление округлённых чисел и искажённой
  многорядной записи.
- `tests/test_harness.py`: незавершённый план, лимит шагов, ошибка в результате инструмента, исправленный повтор
  и независимый успешный вызов, который не должен скрывать прежнюю ошибку; после блокировки Excel план всё равно
  может зафиксировать пропуск шага с причиной.
- Локальная проверка первой обезличенной модели в Excel (`tests/e2e/verify_transaction.py --model путь --mode direct`):
  два сценария с проверенным откатом, 8,4 с вместе с загрузкой. CAPEX +20% меняет DSCR; найденная строка выручки

  формульных ячеек из шока допущений влияние не подтверждается. Это ограничение карты, а не доказательство отсутствия
  экономической зависимости.
- Сквозной `concept_stress` первой обезличенной модели через OpenAI и Microsoft Excel: `PASS`, 9 шагов агента,

## Ограничения

- **Поиск параметров опирается на подписи.** Строка с подписью-кодом («Const», «Other», «тенге») без заголовка блока
  находится плохо, пока LLM не дала ей деловое название. Запрос на другом языке, чем подписи, находит только термины
  из встроенного словаря (около 30 групп слов).
- **Параметры без подписи в строке** (число в середине таблицы с подписью только в шапке столбца) в реестр не попадают.

- **Слова.** Лексикон — русский и английский. Показатель с необычным названием найдёт LLM или закрепит пользователь;
  без LLM он останется в списке «не найдены».
- **Прямой шок** меняет только сам показатель: затраты, которые в модели считаются от объёма, не уменьшатся вместе
  с выручкой. Агент пишет об этом в примечании. Для «честного» падения выручки нужен режим `drivers`.
- **Подгонка в режиме `drivers`** — один пробный пересчёт и линейная пропорция, «в среднем за период». По годам
  изменение показателя отличается от заданного; при слабой связи допущений с показателем (долг) подгонка грубая.
- **Переключатель сценария одной ячейкой** находится по словам в подписи («сценарий», «стресс», «case»).
- **Периоды по вертикали** (годы сверху вниз) не разбираются: такие листы участвуют в пересчёте, но шок на них
  задаётся только диапазоном. Агент предупреждает.
- **`INDIRECT` / `OFFSET`**: связи таких формул в графе не видны. Пересчёт от этого не страдает, но карта зависимостей
  и проверка «шок дойдёт до метрики» могут занижать связи. Агент показывает число таких формул.
- **Граница факт / прогноз** — текущий год; задаётся параметром, из модели не выводится.
- **Листы-близнецы** ищутся по совпадению раскладки. Сценарии, устроенные иначе (блоки на одном листе), как наборы
  не распознаются.
- Быстрый набор тестов с настоящим Microsoft Excel на Mac и сквозной `concept_stress` с внешним LLM на первой
  обезличенной модели пройдены. Вторая модель в этой итерации не проверялась.
