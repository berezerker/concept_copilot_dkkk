# Копилот ДККК · агент для анализа CashFlow-моделей

Локальное приложение для кредитного аналитика. Оно открывает Excel-модель заёмщика и строит её карту и смысловой слой
(какая строка за какой экономический фактор отвечает). Дальше отвечает на вопросы в чате и делает стресс-тесты
пересчётом в настоящем Excel. Готовит черновик заключения для КПКИ.

Цифры в ответах — всегда результат пересчёта модели. LLM решает, что посчитать, и пишет выводы, но сама цифры не придумывает.

---

## 1. Установка (один раз)

Нужно: macOS или Windows, Python 3.11+, Microsoft Excel. Без Excel подойдёт LibreOffice, только медленнее.

```bash
cd ~/Documents/cf_agent
python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                 # затем впишите ключи LLM (раздел 6)
chmod +x *.command                   # macOS: чтобы скрипты запускались двойным щелчком
```

**macOS, первый запуск с Excel.**
- Если система спросит, можно ли Терминалу (Python) управлять Excel, нажмите «Разрешить». Если разрешение случайно
  отклонили: Системные настройки → Конфиденциальность и безопасность → Автоматизация → Терминал → Microsoft Excel.
- При первой загрузке новой модели Excel может предложить восстановить содержимое (так бывает с обезличенными
  моделями). Нажмите «Да». Агент сохранит восстановленную копию, и в следующий раз вопроса не будет.

## 2. Запуск

| Как | Что происходит |
|---|---|
| Двойной щелчок по `start_agent.command` | Перезапускает агента (старый процесс на порту останавливается). Браузер открывается на `http://127.0.0.1:8000`, журнал пишется в `server.log` |
| `python run.py` | То же самое из терминала |
| `http://127.0.0.1:8000/?model=~/Documents/папка/модель.xlsx` | Открыть интерфейс и сразу загрузить модель по пути |

Остановить: закрыть окно терминала или нажать Ctrl+C.

## 3. Работа в интерфейсе

1. **Выберите LLM** в шапке:
   - **OpenAI** — только для обезличенных моделей;
   - **GigaChat** — для реальных моделей во внутреннем контуре;
   - **«Офлайн-сценарий»** — без LLM, для проверки установки.
2. **Загрузите модель.** Перетащите `.xlsx` в левую панель или вставьте путь и нажмите «Открыть».
   - Экспресс-анализ занимает секунды: листы, годы, ключевые метрики, драйверы.
   - Затем LLM делает смысловой разбор строк: около 2 минут при первой загрузке, дальше берётся из кэша.
   - Карточка модели и экономические факторы появляются слева.
3. **Кнопки в левой панели.**

| Кнопка | Что делает | Нужна LLM | Время (модель «bjs») |
|---|---|---|---|
| 🗺 Карта модели | Слои листов от допущений к итогам; сколько драйверов лежит вне Inputs | нет | ~1 с |
| 🔍 Предпроверка | #REF!, числа вместо формул в прогнозе, выбивающиеся формулы, одна метрика с разными значениями на разных листах | нет | ~1 с |
| 🧭 Факторы | От каких экономических факторов (цены, курс, налоги, ставки…) зависят ключевые метрики, их доли и сцепки | для разбора словами | 30–90 с |
| 🧑‍🏭 Отраслевой эксперт | Новость → новые значения выбранных полей с обоснованием → сразу стресс и ковенанты | да | ~40 с |
| 📑 Заключение для КПКИ | Фиксированные 7 шагов: предпроверка → ковенанты → факторы → стресс-пакет → запас прочности → обратный стресс → Монте-Карло; затем резюме и рекомендации | для текста | 4–12 мин |

4. **Вопросы в чат** — своими словами. Агент строит план, сам выбирает инструменты и показывает каждый шаг. Примеры:
   - «Что будет с Net Debt / EBITDA и DSCR, если цены реализации упадут на 10% и на 20%?»
   - «Проверь ковенант Net Debt / EBITDA ≤ 3,5 и DSCR ≥ 1,2: выполняются ли и какой запас прочности по ключевым драйверам?»
   - «От чего на самом деле зависит долговая нагрузка? Разложи по экономическим факторам»
   - «Сделай предпроверку модели и объясни 3 самых важных замечания»
   - «Посчитай CFADS, DSCR, LLCR и сколько долга модель выдержит при DSCR ≥ 1,3»

   Простые вопросы — 0,5–3 минуты, комплексные («оцени устойчивость…») — до 15–20 минут.
5. **Сервис.**
   - **📜 Журнал** — каждый пересчёт Excel, каждый вызов LLM и ошибки в реальном времени. Индикатор в шапке показывает,
     идёт ли расчёт.
   - **⏹ Остановить** — прервать задачу после текущего пересчёта.
   - **▶ Демо-тур** — интерактивная экскурсия по интерфейсу.
   - Любой ответ можно скачать в **Word** или Markdown, стресс-прогоны — в Excel.

Исходный файл не меняется: агент работает с копией (`workspace/`), шоки после каждого сценария откатываются.

**Справочник модели.** Агент работает с любой книгой, а не только с шаблоном Inputs / Outputs. При загрузке он строит
справочник: где лежит каждый показатель (выручка, EBITDA, CAPEX, долг, DSCR…), где он на самом деле считается и как
его шоковать. Поэтому можно писать «стресс по выручке −10 %» или «CAPEX +20 %», не зная, где они в модели.
Справочник виден в карточке слева; попросите в чате «покажи справочник модели», чтобы увидеть его целиком.
Если показатель найден неверно — скажите агенту, какая строка правильная, он закрепит её для этой модели.
Как это устроено и где может ошибаться — [docs/universal_model.md](docs/universal_model.md).

## 4. Скрипты (двойной щелчок в Finder)

| Скрипт | Зачем | Результат |
|---|---|---|
| `start_agent.command` | Запустить или перезапустить агента | интерфейс в браузере, `server.log` |
| `run_eval.command` | Полный E2E-тест на двух обезличенных моделях с LLM-судьёй (~1–2 ч) | `tests/e2e/reports/<время>/report.md` |
| `bench_engine.command` | Скорость пересчёта Excel на обеих моделях, без LLM (~2 мин) | `tests/e2e/bench.log` |
| `diag_calc.command` | Диагностика «стресс не меняет метрику»: итерации Excel, режимы пересчёта | `tests/e2e/diag_calc.log` |
| `record_demo.command` | Запустить агента в режиме записи сеанса для демо | `workspace/demo_rec/<время>/` |
| `build_demo.command` | Собрать интерактивное демо из последней записи | `demo.html` |

## 5. Тесты и оценка качества

**Быстрые тесты** (без Excel и без сети, ~1 мин):
```bash
python tests/test_catalog.py      # универсальность: «чужая» модель без привычных листов и подписей
python tests/test_tools.py        # инструменты на синтетической модели (нужен LibreOffice или Excel)
python tests/test_credit.py       # кредитные инструменты, эксперт и КПКИ (LLM эмулируется)
python tests/test_connectors.py   # полный цикл агента через эмуляцию API OpenAI и GigaChat
python tests/test_excel_engine.py # Excel-движок на эмуляторе xlwings
python tests/test_grading.py      # методика оценки E2E
```

**E2E на реальных моделях** — те же функции, что вызывает интерфейс, без UI:
```bash
python -m tests.e2e.run_eval --model путь.xlsx [--model ...] --provider openai --judge openai --fresh
    [--cases stress_price,kpki] [--no-judge] [--direct-only] [--engine excel]
```
- Кейсы лежат в `tests/e2e/cases.json`: кнопки, 6 вопросов в чат, «Факторы» с разбором, эксперт, КПКИ. Можно добавлять свои.
- `--fresh` очищает кэш модели, чтобы карта и LLM-описания построились заново.
- **Автоматические проверки:** нет ошибок; вызваны нужные инструменты; доля чисел ответа, подтверждённых расчётами
  (<70% → FAIL, <90% → WARN); адреса ячеек в тексте; время; число и длительность пересчётов.
- **LLM-судья** оценивает финальный ответ по трассе расчётов, баллы 1–5: корректность, полнота, польза для кредитчика,
  язык, честность. Плюс пишет, что улучшить.
- Итог по кейсу — PASS / WARN / FAIL. Отчёт сохраняется после каждого кейса, рядом `engine_llm.log`.

Судье передаются ответы и результаты расчётов. Для клиентских моделей используйте только `--provider gigachat --judge gigachat`.

## 6. Настройки (`.env`)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `CF_DEFAULT_PROVIDER` | `mock` | LLM в интерфейсе по умолчанию: `mock` / `openai` / `gigachat` |
| `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_BASE_URL` | —, `gpt-5.4` | OpenAI или совместимый шлюз (vLLM, Ollama, внутренний) |
| `GIGACHAT_CREDENTIALS` или `GIGACHAT_ACCESS_TOKEN`, `GIGACHAT_MODEL`, `GIGACHAT_CA_BUNDLE` | —, `GigaChat-2-Max` | GigaChat; сертификат НУЦ Минцифры — путь к файлу |
| `CF_ENGINE` | `auto` | `excel` / `libreoffice` / `auto` (Excel, при неудаче — LibreOffice) / `none` |
| `CF_HOST`, `CF_PORT`, `CF_OPEN_BROWSER` | `127.0.0.1`, `8000`, `1` | сервер; слушает только этот компьютер |
| `CF_WORKDIR` | `./workspace` | копии моделей, кэш карты и смыслового слоя |
| `CF_SEM_MAX_ROWS` | `1500` | сколько строк LLM описывает при смысловом разборе |
| `CF_EXCEL_VISIBLE` | `0` | `1` — не скрывать Excel во время работы |
| `CF_MAC_BATCH` | `1` | Mac: запись шоков одним скриптом (`0` — по одной записи, медленнее) |
| `CF_CALC_PASSES`, `CF_CALC_MODE` | `1`, `calc` | проходы пересчёта для моделей без циклов; `full` — CalculateFull |
| `CF_RECORD` | `0` | `1` — запись сеанса для демо (обычно через `record_demo.command`) |
| `CF_EVAL_PROVIDER`, `CF_EVAL_JUDGE` | `openai` | LLM агента и судьи в E2E-тестах по умолчанию |

## 7. Интерактивное демо

`demo.html` — настоящий интерфейс копилота, который проигрывает записанный сеанс. Сервер, Excel и LLM для него не нужны,
файл открывается в любом браузере.
1. `record_demo.command` — пройдите в интерфейсе нужный сценарий (обезличенная модель, кнопки, вопросы), закройте окно терминала.
2. `build_demo.command` — в папке появится `demo.html`.
3. В демо справа внизу есть панель:
   - загрузить демо-модель;
   - список записанных вопросов агенту;
   - переключатель «реальное время». По умолчанию длинные паузы сжимаются.

   На вопрос, которого нет в записи, демо честно отвечает списком записанных.

Записывайте только обезличенные модели: всё, что показал интерфейс, попадает в файл (домашняя папка в путях заменяется на `~`).

## 8. Если что-то не так

| Симптом | Что сделать |
|---|---|
| Индикатор долго показывает одну задачу | Откройте 📜 Журнал: если идут строки «пересчёт №…», расчёт работает. Иначе — ⏹ Остановить |
| «LLM ошибка… повтор» в журнале | Сетевой сбой, агент повторит до 3 раз сам |
| Стресс «метрики не изменились» | Строка не влияет на метрику — агент подскажет, какие строки шоковать. Если так по всем факторам — `diag_calc.command` |
| Excel показал диалог | Нажать «Да» / «Предоставить доступ»; если книгу закрыли — движок переоткроет её сам |
| Пересчёт медленный | `bench_engine.command`, лог прислать разработчику |
| Страница не открывается или показывает «Not Found» | Перезапустить `start_agent.command` и обновить страницу |

## 10. Безопасность и данные

- В LLM уходят подписи строк и числа из результатов расчётов, а не файл целиком. Это всё равно данные модели.
  **Реальные модели клиентов — только GigaChat во внутреннем контуре;** внешний OpenAI — только обезличенные.
- Сервер слушает только `127.0.0.1`. Ключи хранятся в `.env`, этот файл в `.gitignore`. Не передавайте `.env` вместе с кодом.
- Шоки применяются к копии модели и откатываются.

## Приложение. Как устроен агент

```
Браузер (static/index.html) ──SSE── FastAPI (app/server.py) ── журнал (app/logbus.py)
                                         │
        ┌────────────────────────────────┼───────────────────────────────┐
  Экспресс-анализ                 Harness (agent/harness.py)        LLM (app/llm)
  workbook/index.py, card.py      план → инструменты → ответ        openai · gigachat · mock
  смысловой слой semantics.py              │
                                  26 инструментов (agent/tools*.py)
                                           │
                                  Движок пересчёта (workbook/engine.py)
                                  Excel (xlwings + пакетный AppleScript) | LibreOffice
```

- **Экспресс-анализ** (без LLM): граф зависимостей «строка ← строка», роли листов по структуре книги (не по названиям),
  наборы сценариев, справочник показателей и главные допущения. Подробно — `docs/universal_model.md`. Кэш — по хэшу файла.
- **Смысловой слой:** паспорт каждой строки, влияющей на метрики (до 10 уровней формул): название, смысл, единицы, блок,
  формула словами, экономический фактор (15 универсальных) и отраслевой подфактор (нефтегаз, электроэнергетика,
  металлургия, девелопмент, ритейл, АПК). LLM размечает строки пакетами по 50. Результат кэшируется.
- **Harness:** первый шаг — обязательно `create_plan`, затем инструменты с отметками шагов, до 32 шагов.
  Промпт требует отделять факты расчёта от гипотез.
- **Инструменты:**
  - справочник: `get_catalog`, `catalog_set`;
  - основа: `get_model_card`, `list_sheets`, `model_map`, `audit_model`, `search_rows`, `read_rows`, `trace_row`, `explain_cell`;
  - стрессы: `run_stress` (цель — показатель справочника, строка, ячейка, диапазон, смысл строки или целый фактор; операции %, +, set, сдвиг во
    времени), `goal_seek`, `find_drivers`, `factor_drivers`, `dependency_analysis`;
  - ковенанты и риск: `covenant_check`, `headroom`, `monte_carlo`, `stress_pack`, `safe_zone`, `reverse_stress`;
  - долг: `lender_metrics` (CFADS, DSCR, LLCR, PLCR, скульптинг), `debt_capacity`;
  - эксперт: `industry_expert`;
  - план: `create_plan`, `update_plan`.
- **Excel-движок:**
  - Mac: открытие через LaunchServices, без запроса доступа; ручной пересчёт, Excel скрыт;
  - итерации для моделей с циклическими ссылками;
  - шок и откат пишутся одним AppleScript, строки читаются одним диапазоном;
  - если книгу закрыли, движок переоткрывает её сам;
  - пересчёт одного сценария — 1–3 с, фактора на сотни строк — 3–9 с.
